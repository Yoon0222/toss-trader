# 토스증권 AI 자동매매 — Phase 1

Phase 1 개발 기반입니다. 기본 모드는 PAPER_TRADING이며, 실제 주문 전송 기능은 없습니다. Python 3.12 Docker 환경을 기준으로 구성했고 Python 3.11도 개발 테스트용으로 허용합니다.

## 실행

프로젝트 폴더에서 Docker Compose가 설치된 환경으로 실행합니다.

```powershell
Copy-Item .env.example .env
# .env의 POSTGRES_PASSWORD를 바꾸세요. URL에 사용할 수 있는 영문·숫자 비밀번호를 사용하세요.
docker compose up --build -d
```

PostgreSQL 준비 → 일회성 Alembic 마이그레이션 → API 실행 순서입니다. PostgreSQL·Redis는 외부 포트를 노출하지 않고 API는 127.0.0.1:8000에만 노출합니다. 운영 배포는 별도 인증·TLS·Secret Manager 구성이 필요합니다.

- API 문서: http://localhost:8000/docs
- 실행 확인: http://localhost:8000/health/live
- DB·Redis 확인: http://localhost:8000/health/ready (연결 실패 시 503)
- 모드 확인: http://localhost:8000/api/status

```powershell
docker compose logs api
docker compose down
```

`down`은 데이터 볼륨을 보존합니다. `.env`와 실제 자격증명은 저장소에 넣지 마세요. Phase 1 컨테이너에는 토스 키를 전달할 필요가 없습니다.

## 로컬 개발 및 테스트

```powershell
py -3.12 -m venv .venv
.venv/Scripts/python -m pip install -r requirements-dev.lock
.venv/Scripts/python -m pip install --no-deps -e .
.venv/Scripts/python -m pytest -q
# 별도로 접근 가능한 PostgreSQL·Redis가 필요합니다.
.venv/Scripts/python -m alembic upgrade head
.venv/Scripts/python -m uvicorn app.main:app --reload
```

Linux에서는 `python3.12`와 `.venv/bin/python`을 사용하세요. 로컬 DB·Redis 주소는 `.env`의 DATABASE_URL, REDIS_URL에서 설정합니다. Compose 내부 서비스에는 `.env`의 POSTGRES_PASSWORD로 만든 주소가 적용됩니다. 설정 비밀값은 SecretStr로 마스킹합니다. 파일 자체의 암호화·키 회전은 운영 단계 작업입니다.

## 실제 데이터 대시보드

http://localhost:8000/ 에서 실제 공식 API 조회 결과만 표시합니다. 샘플 종목·금액·차트·AI 점수·체결 내역은 제거했습니다. 미연결 값은 --이며, 연결 실패를 잔고 0원으로 표시하지 않습니다.

1. 토스 WTS 설정 > Open API에서 키 발급 및 서버 공인 IP 허용 등록.
2. 프로젝트 .env에 TOSS_CLIENT_ID, TOSS_CLIENT_SECRET 설정. 계좌 조회에는 TOSS_ACCOUNT_SEQ 추가. 이는 계좌번호가 아니라 공식 GET /api/v1/accounts의 accountSeq 값입니다. 키는 채팅·브라우저·로그에 노출하지 마세요.
3. 서버 재시작 후 대시보드 새로고침. 시세만 조회할 경우 계좌 식별 설정은 생략할 수 있습니다.

현재 .env에는 빈 인증 항목만 준비되어 있습니다. .env가 이미 있으면 복사로 덮어쓰지 말고 필요한 항목을 병합하세요. Docker 실행에는 .env.example의 POSTGRES_PASSWORD도 별도로 설정해야 합니다.

제공 기능: 국내 TOP_GAINERS/1d 순위 20개, 종목 기본정보, KOSPI/KOSDAQ 현재가, USD/KRW 환율, 최근 캔들, 국내 보유 내역·평가손익, 원화 매수 가능 금액, 진행 중 주문 조회. 주문 생성·취소·정정 호출은 없습니다. 실전 주문은 계속 차단됩니다.

자동 조회 시작 버튼은 30초 주기의 REST 조회이며 WebSocket 실시간 스트림이 아닙니다. 1일 차트는 공식 API의 최근 200분봉으로 제공되며 전일 전체를 보장하지 않습니다. 1주·1개월은 최근 5·22개 일봉입니다. 오래된 원천 시각은 이전 시세로 표시하며 휴장 여부를 추정하지 않습니다.

AI 분석과 실제 계좌의 실현손익 집계·자동매매는 연결 전입니다. 별도 가상 계좌의 규칙 기반 자동매매·위험검사·실현손익 집계는 아래 주간 모의검증에서 수행합니다. 지수 등락률도 원천 현재가 응답에 없으므로 만들지 않습니다. 매수 가능 금액을 현금 잔고나 총자산으로 합산하지 않습니다. 국내 보유 합계는 공식 HoldingsOverview의 KRW 거래 종목 합계 필드이며 USD와 섞지 않습니다.

조회 어댑터: app/market.py. 키/토큰은 서버 메모리에만 보관합니다. 인증 발급은 OAuth POST만 허용하고 데이터는 고정 공식 도메인의 GET만 사용합니다. 성공 캐시 15초, 일부 참조정보 1시간, 오류 캐시 30초, 기본 요청 간격 0.4초. 동시 요청은 직렬화합니다. 한도 응답은 실패로 표시하고 무제한 재시도하지 않습니다. 현재 단일 프로세스/단일 worker 전용이며 다른 서비스와 같은 client 자격증명을 공유하면 토큰 재발급이 서로 무효화할 수 있습니다.

계좌 데이터 응답 no-store, Host 검증 및 출처 검사를 적용했습니다. 로컬 전용이며 다중 사용자 인증을 구현한 상태가 아니므로 외부 네트워크에 공개하지 마세요.

## 매수·매도 방식 (현재 모의검증 기준)

현재 전략 `volume-breakout-v1`은 **실제 1분봉·거래량·호가를 수치로 계산하는 규칙 기반 전략**입니다. AI가 차트 이미지를 해석하거나 LLM 의견으로 주문을 결정하지 않습니다. 뉴스·공시 AI 분석도 현재 진입 판단에 사용하지 않습니다. 아래 조건은 2026-10-27~11-02의 가상자금 검증용이며, 실제 계좌 주문은 차단되어 있습니다.

### 매수: 다음 조건을 모두 충족할 때만 가상 진입

| 구분 | 현재 구현 기준 |
| --- | --- |
| 탐색 대상 | 국내 실시간 거래대금 상위 100종목 중 KOSPI·KOSDAQ 종목 |
| 상승률·유동성 | 당일 상승률 +3~10%, 거래대금 10억원 이상 |
| 분석 데이터 | 당일 완료된 1분봉 최소 22개. 진행 중인 봉과 미래 봉은 제외 |
| 거래량 급증 | 마지막 완료 봉의 거래량이 직전 20봉 평균의 2배 이상이면서 1만 주 이상 |
| 고점 돌파 | 마지막 완료 봉 종가가 직전 20봉의 최고가보다 높음 |
| 가격 추세 | 마지막 완료 봉 종가가 시가보다 높고, 조회한 최근 최대 60개 완료 봉의 거래량 가중 평균가보다 높음 |
| 가격 괴리 | 현재 최우선 매도호가가 신호 봉 종가의 ±1% 이내 |
| 호가 간격 | `(최우선 매도호가 − 최우선 매수호가) / 최우선 매도호가`가 0.5% 이하 |
| 데이터 유효성 | 랭킹 집계 120초 이내, 신호 봉 시작 시각 180초 이내, 호가 15초 이내. 호가가 현재보다 2초 넘게 미래면 거부 |
| 진입 시간 | 공식 거래일의 개장 5분 후부터 청산 시작 전까지. 호가 조회 후 실제 가상 체결 직전에도 시간·기간 재확인 |
| 위험 검사 | 아래 투자 한도·현금·보유·일일 중단 조건 통과 |

여기서 거래량 가중 평균가는 각 봉의 `(고가 + 저가 + 종가) / 3`에 거래량을 곱해 합산한 뒤 전체 거래량으로 나눈 값입니다. **최근 최대 60봉 기반 값**이며, 개장 이후 모든 틱으로 계산한 전일 누적 VWAP과는 다릅니다.

개장 5분 후부터 감시하더라도 22개 완료 봉이 모이기 전에는 매수하지 않습니다. 같은 종목을 이미 보유하고 있으면 추가 매수하지 않으며, 동일 날짜·종목·신호 봉의 중복 가상 매수를 원장에서 차단합니다. 조건을 충족하는 종목이 없으면 거래하지 않습니다.

### 매도: 아래 우선순위로 검사

| 우선순위 | 조건 | 가상 매도 방식 |
| --- | --- | --- |
| 1 | 전일 미청산 보유 또는 당일 청산 시작 시각 도달 | 남은 전량의 청산을 시도 |
| 2 | 가상 매도 추정가가 비용 포함 평균 매수가 대비 −1% 이하 | 남은 전량 손절 시도 |
| 3 | 가상 매도 추정가가 보유 중 기록한 최고 평가가 대비 −2% 이하 | 남은 전량 추적 매도 시도 |
| 4 | 평균 매수가 대비 +3% 이상이고 부분 익절 목표 미완료 | 부분 익절 시작 당시 보유 수량의 50%를 목표로 매도. 정수 내림, 최소 1주 |

평균 매수가에는 매수 수수료를 포함합니다. 매도 추정가는 최우선 매수호가에 불리한 슬리피지를 적용한 값이며, 실제 기록 손익에는 매도 수수료·세금 가정도 추가 차감합니다. 따라서 −1% 손절 조건이 최종 손실을 정확히 −1%로 제한하지는 않습니다.

트레일링 스톱은 부분 익절 이후에만 적용하는 것이 아니라 **보유 중 계속 검사**합니다. 조건이 겹치면 표의 우선순위를 따릅니다. 부분 익절은 유동성 부족으로 나뉘어 체결될 수 있으며 목표 수량과 누적 체결량을 영속 저장합니다.

### 가상 체결·비용·미체결 처리

- 가상 매수 기준은 최우선 **매도호가**, 가상 매도 기준은 최우선 **매수호가**입니다.
- 한 번에 해당 호가의 표시 잔량 **최대 10%**까지만 체결합니다. 한도가 작으면 부분 체결하거나 체결하지 않습니다. 미체결 수량을 실제 증권사에 주문하거나 대기 주문으로 등록하지 않습니다.
- 매수 가격은 호가보다 0.05% 높게, 매도 가격은 호가보다 0.05% 낮게 계산합니다.
- 수수료는 매수·매도 각각 **0.015%**, 매도세금은 **0.2%**를 가정합니다. 실제 계좌에 적용되는 수수료·세율을 뜻하지 않습니다.
- 유효한 호가가 없거나 오래된 시세·역전 호가·단일가 매매 구간이면 체결을 만들지 않습니다. 보호 매도 실패 시 신규 진입을 보류하고 다음 주기에 다시 확인합니다.
- 당일 청산이 실패하면 미청산 가상 보유분을 보고서에 남깁니다. 검증 기간이 끝났다는 이유로 임의 가격으로 강제 체결하지 않습니다.

서버가 약 30초 간격으로 검사하며, 조회 처리 시간만큼 실제 간격이 길어질 수 있습니다. 정상장에서는 09:05부터 진입 감시, 15:00부터 청산을 시도합니다. 변경된 거래시간은 공식 캘린더에 맞춰 반영하며, 청산 시작은 **장 종료 30분 전과 단일가 매매 시작 5분 전 중 빠른 시각**입니다.

가상 체결·현금·보유량·원가·비용은 별도 SQLite 원장에 원자적으로 저장하고 재시작 시 대사합니다. 보고서는 실현 손익과 미청산 평가손익을 구분합니다. PC가 꺼지거나 로그아웃·절전·인터넷 단절 상태이면 감시와 청산을 수행할 수 없습니다.

구현 근거: [전략·스케줄러](app/paper_runner.py), [가상 원장](app/paper_ledger.py). 운영 기간·자동 시작·보고서 위치는 [주간 검증 안내](docs/PAPER_WEEK.md)를 참고하세요. 위 기준은 일주일 성과를 검증할 가설이며 수익을 보장하지 않습니다.

## 시장·계좌 화면 선택

대시보드 상단에서 국장/미장을 선택한 뒤 가상·모의투자/실제 계좌 조회를 선택합니다. 기본은 미국 모의투자이며 URL의 `market=KR|US`, `view=paper|real`로 화면을 유지하고 브라우저 뒤로 가기도 지원합니다.

- 국장 모의: KRW 가상 원장·보유·체결·일별 보고서. 미장 모의: 별도 USD 가상 원장·보유·체결·뉴욕 거래일 보고서.
- 실제 조회: 선택 시장의 실제 보유 평가금액·일일 평가 손익·미실현 손익·매수가능금액·미체결 주문을 공식 API로 조회합니다. 국장은 KRW, 미장은 USD이며 합산하지 않습니다. 매수가능금액은 현금 잔고와 다를 수 있습니다.
- 실제 보유는 국가와 통화를 함께 필터링합니다. 공식 주문 응답에는 국가 필드가 없어 KRW/USD 통화로 구분합니다. 미국 지수는 미연결로 표시합니다.
- 모의 화면에서는 계좌 조회를 요청하지 않습니다. 실제 조회가 실패하거나 원천 값이 미제공이면 오류 또는 `--`로 표시하며 가상 자금으로 대체하지 않습니다.
- 탭 선택은 화면만 변경합니다. 기존 검증 기간·위험 한도·원장·감시 실행 상태를 변경하지 않습니다. 실제 주문은 계속 차단되며 모의 정지·재개는 해당 시장에만 적용됩니다.


### 2026-10-27 미국 모의정책 변경(v2)

사용자 요청에 따라 연속 손실 3체결 기준의 신규 매수 중단을 제거했습니다. 뉴욕 거래일에 손절 또는 손실 매도한 종목은 같은 거래일 동안 제외하고, 다른 종목에서 기존 진입 조건을 충족하면 가상 매수를 계속합니다. 제외 목록은 체결 기록에서 복원하며 한국 자정·서버 재시작으로 해제되지 않습니다. 다음 뉴욕 거래일부터 다시 후보가 됩니다.

일손실 USD200, 신규 진입 5회, 최대 3종목, 종목당 USD1000, 보호매도 및 실전 주문 차단은 유지합니다. 기존 손실·체결·일일 진입 횟수는 초기화하지 않습니다. 국장의 연속 손실 제한은 기존대로 유지합니다. 정확히 일치하는 미국 v1 정책만 v2로 업그레이드하고 원장에 정책 변경 이벤트를 기록합니다. 같은 검증 기간 중 정책이 변경되었으므로 v1·v2 성과를 동일한 고정 전략 성과로 해석하지 않습니다.


### 2026-10-27 종목별 한도 변경

사용자 요청으로 국장·미장 모의투자 모두 고정 한도를 현재 가상 평가자산의 50%로 변경했습니다. 매수 직전 예산은 `min((가상현금 + 보유 수량 × 마지막 평가가 합계) × 0.5, 가상현금)`이며, 매수 수수료와 슬리피지를 반영한 가격으로 정수주를 내림 계산합니다. 실제 계좌 자금은 사용하지 않습니다.

기존 보유 종목은 추가 매수하지 않으며 이번 변경으로 강제 매도하지 않습니다. 평가금액은 마지막 정상 호가 기준으로 최신 실제 청산가능 금액과 다를 수 있습니다. 최초 자산 기준 한도는 국장 500만원·미장 USD5,000이고, 이후 자산 변동에 따라 달라집니다. 기존 일손실 한도·하루 진입5회·최대3종목·미국 손실청산종목 제외는 유지하며, 과거 체결·손익은 초기화하지 않습니다. 정책 변경 전후 성과를 구분해야 합니다.

### 매매 기록 표시
국장·미장 모의 화면에서 매수·매도 기록을 항상 표시합니다. 날짜와 시각은 한국시간이며 최신20건과 전체건수를 구분합니다. 매도 실현손익은 양방향비용과 배분매수원가를 반영한 원장값이고 이익은 빨강(+), 손실은 파랑(-), 0은중립입니다. 매수행은미확정으로표시하며 종목·수량·가격·거래금액·비용·한국어매매이유를함께제공합니다.


### 90분 시간 제한 매도 제거 — 2026-10-27 KST
